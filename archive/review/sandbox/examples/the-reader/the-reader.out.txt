§7 — the order of operations is normative

   1  fetch the profile                     446 bytes, parsed under §2.4's rules
   2  is `anchor` the key I learned?        pukq6VMQM9… — yes
   3  record a recovery list per length     length 1: k = 2 of 3 leaves
   4  walk the chain                        0 links yet: the chain is the anchor key alone
   5  verify the profile's own signature    under the key step 4 ended on
   6  compare the profile against the pin   no pin: nothing to compare
   7  fetch the index, verify, fold         version 5, top 3, 4 live entries
   8  an index that will not verify…        it verified, so there is nothing to note
   9  compare the index against the pin     no pin
  10  fetch every live entry (§7.4)         3 posts and 1 media file
  11  targets above a pinned top (§7.5)     no pin for anyone else: nothing to look at

  verdict  ok

§7.1 — each step supplies what the next one checks

  step 2 before step 4 — the impostor's profile, read by two readers:
    one that learned the thief's key   ok — the chain walks, the file verifies
    one that learned hers              identity: not the identity this reader learned
    Step 4 asks whether a history hangs together. Only step 2 asks whose it is.

  step 4 before step 5 — which key to verify under is the chain's last word:
    her rotated profile, under the anchor key   null
    under the key the chain ends on             verifies
    A reader that verified first would have to guess, and its only guess is the anchor —
    which stops working the first time she rotates.

§7.3 — the notes are not verdicts

  read                                        verdict   note
  after she withdraws post 2                  ok        withdrawn: 2
  mid-rotation: profile moved, index has not  ok        no index I can verify
  after two of the three vouch her back in    ok        recently restored

  Three notes, three ok reads. Promote one to a state and the reader has four states, and
  the fourth fires on an honest withdrawal, an honest rotation, an honest recovery.

§7.2 — an index that will not verify is not an accusation (step 8)

  the same hub, caught mid-rotation, read two ways:
    holding an index it verified itself     ok        no index I can verify
    holding none                            host      the index is not signed by the key the profile ends on

  The pinned reader keeps its own index and hands back its 2 posts. A garbled file, a 404, an
  index signed by a rotated-out key, and an honest host between a rotation's two writes are
  all this, and no reader can tell them apart — so §7.2 asks a cold reader to retry the
  whole read once before it reports `host`.

§7.4 — every live entry is checked before it is handed back

  media ot0dUvs5…   the bytes hash to the address the index lists       true
  post 1            the signature verifies under a key in the chain     the anchor key, two links back
                    its address, and its n, are what index and path say true
  post 4            the same three checks, and 8 opaque slots           text: undefined

  This reader holds no reading key and never looked for one: `encrypted` comes back whole
  and unopened, because opening it is the client's business (§6). Any failure is `host`.

§7.3 — a frozen copy is about the identity, not the host

    a reader that saw the newer profile     identity  an older profile than the one this reader saw
    a reader arriving cold                  ok

  Not `host`: this host is serving exactly what it has. Two claims about one identity are in
  play and this reader saw the newer one, so the question is which of them is her. A cold
  reader has no second claim, and sees an unmarked page (§13.3).

§7.3 — 10 hostile moves, 3 verdicts

  move                                             verdict   what the reader said
  withholds a listed post                          host      post 3 is listed and not served
  serves an older index                            host      an index older than the one this reader saw
  swaps a post for another she signed              host      post 1 is not what the index lists
  serves genuine post 3 at number 1                host      post 1 is not what the index lists
  withholds a listed media file                    host      media file ot0dUv… is listed and not served
  alters the media bytes                           host      media file ot0dUv… is not what the index lists
  substitutes a whole other identity               identity  not the identity this reader learned
  serves a second profile at one version           identity  contested: two profiles at one version
  serves no profile at all                         host      no profile served
  smuggles in a post signed by a key that was hers ok

  distinct verdicts across the battery: 3  (host, identity, ok)

  The last row is why the third verdict is `ok`. A file signed by a key that was hers is not
  a post: the index admits posts (§4), it does not list 9, and the read is ordinary. Nothing
  is left over for a fourth verdict to be, and a conforming reader MUST NOT invent one.
