§3.1 — a reader that learns your key from the host has learned nothing

  the host serves this at https://alice.example/alice/profile:
    name    "Alice"     — signed, so no hub chose it, and no reader may match on it (§3.2)
    anchor  evv4hOQkQbxJ8YdsUDb-r-VyePNU-YfTD9adgWQdJgo
  and it is a perfectly good file: signed by the key its chain ends on, chain walks.

  learned from the profile itself   ok          ← trust on first use
  learned out of band (§3.1)        identity — not the identity this reader learned
  the same check on alice's own     ok

§3.1 — the link: the key rides in the fragment, so the server never sees it

  link            https://alice.example/alice#pukq6VMQM9Sbp4ae71bJjcKbLLpFuWi47cDS60xH7CY
  the server gets GET /alice — a fragment is not part of a request (RFC 3986 §3.5)
  location        https://alice.example/alice   where to fetch
  key learned     pukq6VMQM9Sbp4ae71bJjcKbLLpFuWi47cDS60xH7CY   43 characters, 32 bytes
  a plain browser follows the same link to the same page and ignores the fragment.

  the reader compares it with the profile's `anchor`, and on mismatch refuses:
  host serves its own profile here → identity: not the identity this reader learned

  That is what alice reads down the phone, and what her daughter types into the app.
  Nobody says the 43 characters out loud, and no user is ever shown them (§3.1).

§3.1 — 66 bits, and why not 55

  the wordlist   2048 words = 2^11, so one word carries 11 bits
  six words      66 bits, 73786976294838206464 keys to search
  five words     55 bits,    36028797018963968 — 2048x less work
  §3.1 puts the difference plainly: at 66 bits grinding a colliding key is centuries
  of GPU time; at 55 it is not. The extra word costs one second on a phone call.

§3.1 — the code distinguishes identities, not versions

  alice, version 1   chain ends on pukq6VMQ…   inflict view trash better source icon
  alice, version 3   chain ends on 17Ffa8rS…   inflict view trash better source icon
  the host above     chain ends on evv4hOQk…   machine world urban obvious vital thing

  Two versions of one identity share the anchor key, so they speak the same six words —
  even though the second has rotated once and been restored once. The code tells alice
  from a stranger; it cannot tell one branch of alice from another. Hence §3.6.

§3.6 — the exit from contested: the same routes MAY carry the key the chain ends on now

  alice's branch  anchor → alice/rotated → alice/restored   ends on 17Ffa8rS…
  a thief's       anchor → a key of his own                 ends on Tt-buDzc…
  over the anchor        both say  inflict view trash better source icon
  over alice's current   comfort carbon code disorder happy chat
  over the thief's       witness circle doll furnace lazy stool

  A reader stuck at contested and handed the middle line MUST follow the branch whose
  chain contains that key, and pin there. Six words over a *key*, not over an identity,
  is what makes that possible. `examples/contest/` has §3.6 itself.
