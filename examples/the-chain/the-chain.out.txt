  The first link MUST be {"key": <anchor>} and its key MUST equal `anchor`. Every later
  link has one shape and differs only in whether it carries `sig`, `vouchers`, or both.

§3.3 — every link carries the recovery list as it stood before it

  a reader meeting alice for the first time at chain length 3 holds no list at 1 or 2:
  walk with a list at length 1 only   null   nothing to judge the restore by
  lists adopted from the chain        lengths 1, 2, 3, all the same list
  walk again                          current key 17Ffa8rS…

  The carried copy is what a reader with NO list at that length adopts; a reader already
  holding one ignores it (§3.6 rule 3). The list itself is `examples/recovery-list/`;
  what happens when two chains disagree is `examples/contest/`.

§3.3 — vouchers may be added to a link after it was made

  the rotation alice made alone   key kAIz_MtY…  recovery {k:2, 3 leaves}      sig nWLFgpsi…
  backed later by her people      key kAIz_MtY…  recovery {k:2, 3 leaves}      sig nWLFgpsi…   vouchers mum, sis
  same key moved to: true, same sig: true, vouchers that now count: 2

  Nothing after this link is disturbed. That is what lets her win a contest AT that link
  (§3.6) without restoring again and abandoning every key and post that came after it.

§3.3 — a restore changes the key and nothing else

  pinned at version 2   chain length 2, locations ["https://alice.example/alice"]
  served version 3      chain length 3, the new link unsigned — a restore
    locations unchanged                    ok
    locations changed in the same version  identity   a restore changed more than the key

  Whoever vouched moved the key. They did not move the identity to a hub of their own.

§3.3 — a key rotated away from keeps its posts valid

  post 1, signed by the anchor key, verified under the chain's keys:  by pukq6VMQ…
  the chain now ends on 17Ffa8rS…, and the anchor is still in it: true

  There is no revocation message anywhere in Open Feed. The old key is closed by what it may
  no longer do: it cannot sign an index (§4.6 — the index MUST be signed by the key the chain
  currently ends on; `examples/the-index/`) and it cannot hold a number against the owner (§8.5).

§3.5 — changing the key means writing the profile and the index again, in that order

  an index signed by the key alice just left, verified under the current key: null

  The index MUST be signed by the current key (§4.6), and a hub that verifies writes checks the
  index against the profile it holds (§8.4) — so the profile goes first. Between the two writes
  an honest host serves an index its own profile disowns; §7.2 answers that (not an accusation).

Every line above is asserted.
